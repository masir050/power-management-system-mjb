# 评测报告 · 100 题

> 数据采集：2026-11-12（216 块版），power-rag 模块，`/eval?mode=rrf-rerank` + `/ask` 端到端。
> 语料：`data/docs/` 18 份文档 → 216 个知识块（每份 12 节）＝ 15 份运维规程 + 3 份用户服务文档（停电复电 / 电费缴费 / 安全用电报修）。
> 原始数据：`eval-raw-100.json`（100 题检索明细）、`answer-sample-30.json`（30 条答案原文）、`role-demo.json`（三角色口吻对照）。

## 一、结论

| 指标 | 结果 | 测法 |
|---|---|---|
| 检索 Top-3 命中 | **100.0%**（70 / 70） | 100 题全量，否定题不计入命中分母 |
| 检索 Top-1 命中 | **98.6%**（69 / 70） | 同上 |
| 答案正确率 | **100.0%**（30 / 30） | 人工抽检 30 条（直答 15 + 跨段 8 + 否定 7） |
| 否定类拒答准确 | **100.0%**（30 / 30） | 30 条否定题全量，重排分 < 0.5 即拒答 |
| 平均响应 | **2.0 s**（最慢 6.0 s） | 30 条样本（直答 15 + 跨段 15，OPERATOR 档），`/ask` 端到端 |
| 单次 token | **896**（prompt 787 / completion 110） | `/stats` 差值 26887 ÷ 30 |

三条判定标准（先定标准再判，避免"看着差不多就算对"）：

1. **结论对**：答案里的数字/等级/顺序与规程原文一致，且回答了问题本身；
2. **依据对得上来源**：答案标注的「资料 N」确实包含那句话，不是从别的块拼的；
3. **没编造数字**：出现原文没有的数值、时限、设备名，一律判错。

本次抽检里数字阈值（95℃、198–242V、65K、1000MΩ、1.5m、0.2 级、105%、5 分钟、50μA、±5% 等）均能在原文找到出处；第 05 题两份规程对 110kV 绝缘电阻口径不同，模型如实指出差异并建议先确认设备类型，未硬凑一个数。

## 二、题库构成

| 类型 | 数量 | 覆盖 | 出题口径 |
|---|---|---|---|
| 直答 | 40 | 15 份规程全覆盖（每份 2–6 题） | 答案落在单一小节，问法换同义词，不抄原文 |
| 跨段 | 30 | 同上 | 需要两节拼起来（如「96℃ + 冷却器全停 25 分钟」要同时用分级表和冷却器条款） |
| 否定 | 30 | 同领域但库里确实没有 | 换流站阀厅、GIS 气室、消防水带口径、镀锌层厚度、家用充电桩报装…不是「今天星期几」这种离谱题 |

文件：`data/eval/questions.csv`，三列 `问题,期望出处,类型`。
否定题的期望出处写 `NONE`，评测接口据此把它们从命中率分母里剔除。

> 题库随语料一起修过两轮：第一轮（180 块）换掉 4 道被扩充语料覆盖的否定题；本轮（216 块）新增 3 份用户服务文档后，
> 否定题「欠电费多久会拉闸」被《电费与缴费指南》第 5 节合法覆盖（欠费 15 天预通知 / 30 天停电，重排分 0.793）——这不是检索错了，
> 是题过时了，已换成语料确实没写的「家用充电桩报装怎么申请」（重排分 0.020）。

## 三、复现方式

```bash
# 1. 起服务后跑检索评测（不调大模型，只算检索与拒答）
curl "http://localhost:8088/eval?mode=rrf-rerank"

# 2. 答案抽样：/ask 走完整链路，前后对 /stats 取差值；role 决定回答人设
curl "http://localhost:8088/stats/reset"
curl "http://localhost:8088/ask?q=油温到多少度算危急缺陷&role=OPERATOR"
curl "http://localhost:8088/stats"
```

前置条件：`pgv`（pgvector，216 块）、`power-redis`、`neo4j` 三个容器在跑；`data/docs/` 18 份 md 已灌库。
换机器复现前先确认 `vector_store` 里是 216 行，否则分母不对、数字没意义。
抽检前记得清 `ans:*` 缓存键，否则第二次问同一句会命中缓存、耗时变成 5 毫秒。

## 四、检索结果明细

### 4.1 Top-1 没中的一题（Top-3 里都在）

| 问题 | 期望 | 实际 Top-1 | 重排分 |
|---|---|---|---|
| 开关跳闸后录波啥时候调取，先看什么 | 故障录波分析导则 | 开关跳闸分析导则 | 0.792 |

真·跨文档：问句前半"开关跳闸后"天然贴《开关跳闸分析导则》（那节确实在讲跳闸后先看什么），
后半"录波调取"才是《故障录波分析导则》的内容。两份文档都在 Top-3，抽检时答案把两边的条款拼全了。

### 4.2 拒答闸门的边界（这套数里最该记住的一条）

| 样本 | 重排分 | 说明 |
|---|---|---|
| 正例最低 | **0.554** | 「录波里 CT 饱和长什么样会害保护怎么动」 |
| 正例次低 | 0.597 | 「轻瓦斯动作同时油温往上走说明什么」 |
| 阈值 | 0.500 | `HybridRetriever.REJECT_THRESHOLD` |
| 否定最高 | **0.413** | 「变压器油多久化验一次」——被《变压器运行规程》油质条款误召回 |

分界窗口 **(0.413, 0.554]，宽 0.141**，比 180 块时（0.132）又略宽：新增的用户服务文档与规程主题完全分离，
没有出现"两份文档抢同一个主题"的情况。
但阈值仍是 0.5 这一定值，**换语料或换 reranker 必须重新标定**，不能直接搬。

| 指标 | 数值 | 说明 |

## 五、回答分档（三类提问者三套人设）

`/ask` 与 `/ask2` 新增 `role` 参数：`CUSTOMER`（用电用户）/ `OPERATOR`（运维，默认）/ `ADMIN`（管理员）。
人设在 `service/RolePrompts.java`，SYSTEM 是缓存 key 的一部分，同一问题三种角色的答案天然隔离。
前端默认跟随登录角色，面板里可手动切换；CUSTOMER 不显示"告警研判"页签。

同一问题三个口吻的实测对照（完整原文见 `role-demo.json`）：

| 问题 | CUSTOMER | OPERATOR | ADMIN |
|---|---|---|---|
| 欠电费了会停电吗 | "不是一欠就停，中间会先提醒你好几次"，讲清三步提醒、15/30 天、违约金，落在"缴清后 30 分钟复电" | 四种停电类型定性 + 条款数字直给 | 按"提醒→预通知→执行"编号步骤，突出每步时限与复电承诺 |
| 主变过温告警怎么处理 | 先说明"这是变电站里的事，跟家里用电不是一回事"，再按人话讲三档怎么判 | 75/85/95℃ 判据 + 10K 温差 + 3 分钟确认，规程条款直给 | "谁在几分钟内确认→判断类型→现场检查→按级抄录"的责任与时序链 |

## 七、这套数怎么用

简历 / 讲稿里可以直接写：

- 自建 **18 份文档、216 个知识块**的中文语料库（15 份运维规程 + 3 份用户服务文档），混合检索（向量 + BM25 → RRF → 重排）**Top-3 命中 100%、Top-1 98.6%**；
- **否定类 30 题拒答准确率 100%**，拒答判据建在 Cross-Encoder 重排分上（阈值 0.5），不调大模型即返回，1 秒级；
- **按提问者身份分档回答**：用电用户 / 运维 / 管理员三套人设，同一问题三种口吻，答案缓存按角色隔离；
- 答案正确率 **100%**（抽检 30 条，标准：结论对 / 依据对得上来源 / 不编数字）；
- 单次问答平均 **2.0 秒、896 token**；命中缓存后降到 5–7 毫秒。

被追问时要说清楚的三件事：

1. 这套指标衡量的是**这个 216 块小库上的检索与作答质量**，不是通用电力问答能力；
2. Top-3 100% 的原因是语料主题边界清晰（规程与用户文档互不重叠），**难度不在检索而在拒答与跨段**；
3. 阈值 0.5 的实测窗口是 0.141，语料再扩一版就得重新标定，**不能把 0.5 当常数**。

## 八、已知偏差与限制

| 限制 | 说明 |
|---|---|
| 语料是自写模拟文档 | 18 份 md / 216 块，结构与真实电网规程相近，但覆盖面远小于真实资料库；块由二级标题切分，每份 12 节 |
| 角色分档只有三档 | CUSTOMER / OPERATOR / ADMIN 由前端传入、可被恶意改参切换；人设只影响口吻与详略，事实内容仍只来自语料 |
| 题库是我按章节出的 | 已换同义词、去掉原文句式，但知识点边界仍比真实提问清晰；真实提问会跨文档、带口语和错别字 |
| 拒答阈值余量有限 | 正例最低 0.554 / 否定最高 0.413，窗口 0.141；换 reranker 或换语料必须重跑标定 |
| 平均响应 2.0s | 比 180 块时（1.47s）略涨：SYSTEM 分档变长 + 语料覆盖变广；`/diagnose` 多工具链路实测 10~13s |
| token 随提示词变长微涨 | 832 → 896（+8%），主要来自 SYSTEM 的分档要求；命中缓存后无此开销 |
| token 只覆盖非流式 | `/chat/stream`、`/chat/mem` 的 usage 在流末帧，未聚合，所以 `/stats` 的 token 只含 `/ask` 与 `/ask-fb` |
| 正确率是单判 | 由一人按三条硬标准判定，没有第二人复核；跨段题在「答得全不全」上有主观余地 |
